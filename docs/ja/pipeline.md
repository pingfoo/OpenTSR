ステージをオフにしたとき（`null` の意味）の、実装上の意味：

- tracker オフ：各候補がその1フレーム限りの標識になる（負のトラックID）。
- memory オフ：TTLゼロのメモリ。追跡された標識は見えている間はトラック単位の履歴を保ち、欠けた最初のフレームで忘れられる。これにより「メモリなしの追跡」を測れる。
- classifier オフ：検出器のクラスが出力される（検出器が細粒度ならその細粒度クラス、そうでなければ粗粒度の族。メッセージの `fine` は `null`）。
- decision オフ：フレームごとの argmax。
- reader、relevance、fusion、defense オフ：ステージを飛ばす（すべての標識を関連ありとみなす、カメラのみ、強化なし）。

## 2. 最初のL3セットとしてのSTS

- Zenodo レコード 19666339（Larsson と Felsberg、2026-04-20 アップロード、`traffic-signs_dataset.zip`、15.8 GB）は CC BY 4.0 でライセンスされている。2026-11-01 に Zenodo API で確認した。CVL のページには2011年の「承認なしに商用利用してはならない」という文がまだ残っている。OpenTSR が利用し引用するのは Zenodo のコピーである。メンテナは著者に連絡する意向を保っている。
- アノテーションファイル（`annotations.txt`、1,970行と1,807行）だけで CVL からダウンロードでき、イベント正解を作るにはそれで足りる。フレーム（Part0、1セットあたり約1.5 GB）は検出器を走らせるときにのみ必要になる。
- 形式：`<burst>Image<n>.jpg:STATUS, x_max, y_max, x_min, y_min, TYPE, NAME;...`。STATUS は VISIBLE / BLURRED / OCCLUDED / SIDE_ROAD、NAME は6種類に属する20種類。SIDE_ROAD は関連性ラベルであり、トラックの多数派の状態であればイベントの `relevant = false` になる。
- タイミング：バーストの接頭辞は Unix 秒であり、生フレームの5枚ごとに1枚がアノテーションされている。生のフレームレートは文書化されていないため、当面 `time_s = burst + (n - 1) * 0.4`（約 2.5 fps。58秒で132フレームのバーストと整合する）とする。10秒を超える間隔でシーケンスを切ると、Set1 は100シーケンス、Set2 は51シーケンスになる。
- リンク後のイベント：Set1 839（関連あり752、単フレーム219）、Set2 866（関連あり808、単フレーム221）。単フレームの割合は疎なラベル付けの性質であってリンカの性質ではない。90 km/h で通過する標識が 12 px 以上で見えるのは、アノテーションされたフレームでおよそ1枚から2枚分である。

リンカ（`events.link_tracks`）は決定的で、イベントファイルの `meta.linker` にすべてのパラメータが記録される。IoU 0.3 で即リンク。それ以外は、直近2箱からの中心と大きさの線形外挿で、予測サイズの 1.5 倍の半径以内。1箱のトラックは標識サイズの5倍以内の箱を受け付ける。サイズ比は最大 2.0。細粒度ラベルは OTHER / URDBL を除いて一致が必要。トラックはアノテーションされていないフレーム1枚分は生き残る。模擬実行で2つの変種を試し、捨てた（STS のカメラは道路の中心を向いていないため誤りである「消失点から外向き」規則と、同じ族の隣接標識を併合してしまう、外挿が外れたときの1箱フォールバック）。リンカはまだフレームそのものと照合していない。Part0 をダウンロードしたら最初にそれを行う。

## 3. テストを書きながら決めた評価器の規約

- メッセージは、同じフレーム（または、n枚ごとにラベル付けされたデータセット向けに、`match_gap` 枚以内の最も近いアノテーション済みフレーム）でそのトラックの箱とアノテーション箱が IoU 0.5 以上で重なるイベントに帰属させる。記憶中（見えていない）の標識は、最後に見えたときのイベントを保持する。
- 1つのイベントに1フレームで複数のシステムトラックが帰属する場合、最高信頼度のメッセージだけを数える（表示に出るのはそれである）。これがないと、標識に付いた記憶中の1フレームの幻が揺れ回数を3倍にした。
- 「標識だがクラス不明」を意味するラベル（`URDBL`、`UNREADABLE`）は、クラス変化にも誤クラスにも数えない。
- アラートは状態が `new` または `update` のメッセージである。`keep` のメッセージはアラートに数えないため、フレームごとのシステム（すべてのメッセージが `new`）は投票システムより多くのアラートを持つ。したがって適合率は絶対の誤警報件数を横に添えて報告する。
- イベント再現率は関連ありのイベントに対して計算する。`event_recall_all` は脇道の標識を含む。

## 4. 模擬アブレーション（ハーネスの確認のみ。結果ではない）

`make ablation-sim` は `full_sparse.yaml` の全変種を、正解にシード固定のノイズ（見逃し10%、16 px 未満はさらに見逃し30%、ラベル反転10%、5%のフレームに幻の箱）を加えた検出で、STS の両セットに対して実行する。表は `runs/ablation/sts_sim/table.md` に出る。この実行がハーネスについて示すこと（模擬の数値であり、結果として引用してはならない）：

- ステージをオフにすると、変わるべき列だけが変わる。分類器なしでは細粒度の再現率がゼロになり粗粒度の再現率は変わらない。判定なしはフレームごとのストリームと一致する。追跡なしと判定なしは一致する（投票にはトラックが必要）。
- 幾何的な関連性判定の暫定実装（中心が画像の外側20%にある標識は「関連なし」）は、通過する標識が画像の端に達するため、STS で再現率を約10ポイント下げる。計画どおり、学習による関連性ヘッドで置き換える。
- 2フレームでの確定を要求すると（`confirm_2` プリセット。`full.yaml` が 10 fps 以上で行うこと）、2秒ごとにラベル付けされたセットでは再現率が半減する。フレーム数のパラメータはフレームレートごとに設定しなければならない。次のステップは秒で表現することである。
- 1フレームでの確定なら、投票はアラートを 5,659 から 2,171 に、揺れを1イベントあたり 0.43 から 0.32 に減らし、細粒度の再現率は同じ（0.73）で、絶対の誤警報は約40%減る。
